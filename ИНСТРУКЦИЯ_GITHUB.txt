КАК ЗАГРУЗИТЬ ПРОЕКТ «ПОРТРЕТ ЛИЧНОСТИ» НА GITHUB
==================================================

GitHub — сайт для хранения кода. Нужен, чтобы (1) показать код преподавателю по
ссылке и (2) подключить хостинг (например, Render), который берёт проект
из GitHub. Ниже два способа: А — через браузер (проще, ничего не надо
устанавливать) и Б — через Git (как делают разработчики). Выберите один.

Содержание
  1. Подготовка папки проекта
  2. Регистрация на GitHub
  3. Создание репозитория
  4. Способ А: загрузка через браузер
  5. Способ Б: загрузка через Git (командная строка)
  6. Способ Б-2: через GitHub Desktop (с кнопками)
  7. Проверка: как понять, что всё загрузилось правильно
  8. Как обновить проект после изменений
  9. Подключение к Render (хостинг)
  10. Если не работает
  11. Шпаргалка


1. ПОДГОТОВКА ПАПКИ ПРОЕКТА
---------------------------
1.1. Распакуйте portrait_project.zip. Нужная папка — та, где лежат:
         portrait/   tests/   requirements.txt   и текстовые файлы.
     Если внутри ещё одна папка portrait_project — зайдите в неё.

1.2. НЕ загружайте на GitHub лишнее:
     - папку venv (виртуальное окружение — тяжёлая и не нужна);
     - папки __pycache__ (служебные файлы Python);
     - файл portrait.json (создаётся при запуске консольной версии).
     Если вы ещё не запускали проект, этих файлов у вас нет — всё в порядке.
     Если запускали — удалите их из папки перед загрузкой (способ А) или
     используйте файл .gitignore (способ Б, п. 5.2).

1.3. Файл requirements.txt ДОЛЖЕН лежать в корне репозитория (не внутри лишней
     вложенной папки). Иначе хостинг не найдёт зависимости.


2. РЕГИСТРАЦИЯ НА GITHUB
------------------------
1) Откройте https://github.com и нажмите «Sign up».
2) Введите электронную почту, придумайте пароль и имя пользователя (оно
   будет в ссылке на ваш проект, например github.com/ivan-petrov).
3) Подтвердите почту кодом из письма.
4) Если GitHub предложит выбрать тариф — выбирайте бесплатный (Free).


3. СОЗДАНИЕ РЕПОЗИТОРИЯ
-----------------------
Репозиторий — это «папка проекта» на GitHub.

1) Войдите на github.com. В правом верхнем углу нажмите «+» → «New repository».
2) Заполните:
     Repository name:  portrait-lichnosti   (латиницей, без пробелов)
     Description:      необязательно, например «Модуль психологического
                       тестирования»
     Public / Private: Public — виден всем (проще для показа и подключения
                       хостинга). Private — только вам (хостинг тоже сможет
                       подключиться, но придётся выдать ему доступ).
3) Галочки «Add a README file», «.gitignore», «license» НЕ ставьте, если
   собираетесь загружать способом Б (с Git). Для способа А можно оставить
   пустым.
4) Нажмите «Create repository».

Откроется страница нового пустого репозитория. Адрес будет вида:
     https://github.com/ВАШ_ЛОГИН/portrait-lichnosti


4. СПОСОБ А: ЗАГРУЗКА ЧЕРЕЗ БРАУЗЕР (БЕЗ УСТАНОВКИ GIT)
-------------------------------------------------------
1) На странице пустого репозитория найдите ссылку «uploading an existing file»
   (в тексте «…or upload an existing file») и нажмите на неё.
   Либо: кнопка «Add file» → «Upload files».

2) Откройте на компьютере папку проекта (ту, что из п. 1.1).
   Выделите ВСЁ содержимое (Ctrl+A) — папки portrait и tests, а также файлы
   requirements.txt и текстовые файлы.

3) Перетащите выделенное мышью в окно браузера на область загрузки.
   Папки загрузятся вместе с вложенными файлами (в Chrome, Edge и Firefox
   это работает). Дождитесь, пока в списке появятся все файлы.

   ВАЖНО: перетаскивайте именно содержимое папки, а не саму внешнюю папку
   portrait_project — иначе requirements.txt окажется внутри вложенной
   папки, а не в корне.

4) Прокрутите страницу вниз. В поле «Commit changes» можно написать
   сообщение, например: «Первая версия проекта».
   Оставьте выбранным «Commit directly to the main branch».
   Нажмите зелёную кнопку «Commit changes».

5) Подождите. Через несколько секунд вы увидите список файлов в репозитории.

Ограничения загрузки через браузер: за один раз GitHub принимает ограниченное
число файлов (около 100) и файлы не больше 25 МБ. В этом проекте около 25
файлов, так что всё поместится. Если когда-нибудь файлов будет больше —
загружайте частями или используйте способ Б.


5. СПОСОБ Б: ЗАГРУЗКА ЧЕРЕЗ GIT (КОМАНДНАЯ СТРОКА)
--------------------------------------------------
5.1. Установка Git (один раз).
     Windows: скачайте установщик с https://git-scm.com/downloads и пройдите
              его, оставляя настройки по умолчанию.
     macOS:   в терминале выполните   git --version   — если Git нет, система
              предложит установить инструменты разработчика.
     Linux:   sudo apt install git
     Проверка:   git --version     (должна вывести номер версии)

5.2. Файл .gitignore (чтобы не загружать лишнее).
     В корне проекта (рядом с requirements.txt) создайте текстовый файл с
     именем  .gitignore  (с точкой в начале, без расширения .txt) и таким
     содержимым:

         venv/
         __pycache__/
         *.pyc
         portrait.json
         .vscode/

     На Windows проще создать файл в VS Code или командой в cmd:
         echo venv/> .gitignore

5.3. Представьтесь Git (один раз на компьютере):
         git config --global user.name "Ваше Имя"
         git config --global user.email "почта-от-github@example.com"
     Почта — та, что вы указали при регистрации на GitHub.

5.4. Загрузка проекта. Откройте терминал В ПАПКЕ ПРОЕКТА (где лежит
     requirements.txt) и выполните по порядку:

         git init
         git add .
         git commit -m "Первая версия проекта"
         git branch -M main
         git remote add origin https://github.com/ВАШ_ЛОГИН/portrait-lichnosti.git
         git push -u origin main

     Адрес в строке git remote add... скопируйте со страницы своего
     репозитория (зелёная кнопка «Code» → вкладка HTTPS).

5.5. Вход в аккаунт.
     При первом git push откроется окно браузера (или предложат войти):
     авторизуйтесь в GitHub и разрешите доступ. Если терминал просит пароль,
     обычный пароль от аккаунта НЕ подойдёт: GitHub требует вход через браузер
     или «personal access token» (Settings → Developer settings → Personal
     access tokens → создать токен с правом repo, вставить его вместо пароля).
     Самый простой путь — способ Б-2 (GitHub Desktop) или способ А.

5.6. После успешного push обновите страницу репозитория на GitHub — файлы
     появятся.


6. СПОСОБ Б-2: GITHUB DESKTOP (С КНОПКАМИ)
------------------------------------------
1) Скачайте приложение https://desktop.github.com и войдите в свой аккаунт.
2) Меню File → «Add local repository…» → выберите папку проекта.
   Если приложение скажет, что это не репозиторий, нажмите на предложенную
   ссылку «create a repository here».
3) Слева появится список файлов. Внизу в поле «Summary» напишите
   «Первая версия проекта» и нажмите «Commit to main».
4) Вверху нажмите «Publish repository». Название оставьте portrait-lichnosti,
   выберите Public (или Private) и нажмите «Publish repository».
5) Готово: репозиторий на GitHub.


7. ПРОВЕРКА: КАК ПОНЯТЬ, ЧТО ВСЁ ЗАГРУЗИЛОСЬ ПРАВИЛЬНО
------------------------------------------------------
Откройте страницу репозитория. В КОРНЕ (на главной странице репозитория) вы
должны увидеть:
     portrait/            (папка)
     tests/               (папка)
     requirements.txt
     ИНСТРУКЦИЯ_ПО_ЗАПУСКУ.txt, ЛОГИКА_И_ПРОЕКТ.txt
Откройте папку portrait — внутри должны быть api.py, engine.py, scoring.py,
папки methods и static и другие файлы.

Если вместо этого вы видите одну папку portrait_project, а в ней всё остальное —
вы загрузили внешнюю папку. Исправление: удалите репозиторий (Settings → внизу
«Delete this repository») и создайте заново, либо перенесите файлы (проще
пересоздать и загрузить содержимое папки, как в п. 4).


8. КАК ОБНОВИТЬ ПРОЕКТ ПОСЛЕ ИЗМЕНЕНИЙ
--------------------------------------
Способ А (браузер): в репозитории «Add file» → «Upload files», перетащите
  изменённые файлы (с теми же путями) и нажмите «Commit changes».
  Отдельный файл можно открыть и править карандашом (значок «Edit»).
Способ Б (Git): в папке проекта выполните
         git add .
         git commit -m "Что изменили"
         git push
GitHub Desktop: «Commit to main» → «Push origin».
Если репозиторий подключён к Render, после обновления он сам пересоберёт сайт
(это занимает несколько минут).


9. ПОДКЛЮЧЕНИЕ К RENDER (БЕСПЛАТНЫЙ ХОСТИНГ)
-------------------------------------------
1) На https://render.com зарегистрируйтесь через кнопку «GitHub».
2) New → Web Service → выберите репозиторий portrait-lichnosti.
   Если репозитория не видно — нажмите «Configure GitHub App» и разрешите
   Render доступ к этому репозиторию.
3) Заполните:
     Runtime:        Python
     Build Command:  pip install -r requirements.txt
     Start Command:  uvicorn portrait.api:app --host 0.0.0.0 --port $PORT
     Instance Type:  Free
4) Нажмите «Deploy». Через несколько минут появится адрес вида
     https://portrait-lichnosti.onrender.com
5) На бесплатном тарифе сайт засыпает после примерно 15 минут без обращений,
   а первое открытие после «сна» может занимать 30–60 секунд. Откройте сайт
   за 5–10 минут до защиты, чтобы он проснулся.
Условия бесплатных тарифов могут меняться — сверяйтесь с сайтом сервиса.


10. ЕСЛИ НЕ РАБОТАЕТ
--------------------
«git» не является командой / command not found
  → Git не установлен или терминал открыт до установки. Установите Git (п. 5.1)
    и откройте терминал заново.

fatal: not a git repository
  → Вы не в папке проекта или не выполнили git init. Перейдите в папку, где лежит
    requirements.txt, и повторите шаги с git init.

error: remote origin already exists
  → Адрес уже добавлен. Замените его:
         git remote set-url origin https://github.com/ВАШ_ЛОГИН/portrait-lichnosti.git

Authentication failed / Permission denied / просит пароль
  → Обычный пароль GitHub для Git больше не принимается. Войдите через браузер
    (появится окно авторизации), создайте personal access token (п. 5.5) или
    используйте GitHub Desktop / способ А.

rejected … (fetch first) / non-fast-forward при git push
  → В репозитории уже есть файлы, которых нет у вас (например, README,
    созданный на сайте). Самый простой выход для нового проекта: удалите
    репозиторий на GitHub и создайте заново пустым (без README), либо
    выполните   git pull origin main --allow-unrelated-histories   и повторите push.

Файлы не перетаскиваются в браузер
  → Попробуйте другой браузер (Chrome/Edge) или нажмите «choose your files»
    и выберите файлы вручную (но тогда папки придётся загружать по одной,
    сохраняя структуру — удобнее способ Б-2).

На Render: ошибка «Could not open requirements file»
  → requirements.txt лежит не в корне репозитория (п. 7). Исправьте структуру.

На Render: ModuleNotFoundError: No module named 'portrait'
  → Папка portrait лежит не в корне репозитория, а во вложенной папке. Либо
    перенесите файлы в корень, либо в настройках Render укажите «Root Directory»
    (имя вложенной папки).
